# Persistent template editor

Choose **Create template** after opening a source world. The editor reads actual blocks at a specific Y, including air under a roof or underground; it is not a surface-height projection. Source reading and capture currently support exact stable Java 26.2/4903 and 26.3/5023 vanilla dimensions. Unknown sections, unreadable chunks and unsupported schemas are reported rather than treated as air.

Choose **Pick two corners**, click the first block, change Slice Y if needed, then click the opposite block. The inclusive cuboid becomes the selection. Numeric From/To coordinates and Lower/Upper Y provide the same control. **Add** and **Remove** refine a single cell, rectangle, cuboid or detached component. One persisted sparse selection is shared by every height and camera position in that source dimension. Selecting air differs from excluding a cell. Editing a draft does not rewrite a previously saved template.

Pan with the Pan tool, right-drag or arrow keys. Plus/minus or the wheel change the visible window from 8×8 to 64×64 cells. X/Z centers and a Y slider provide exact navigation. Offscreen selections remain selected, including detached pieces far away; the preview never allocates the enclosing bounding volume. A slice requests at most 16 chunks per asynchronous worker batch and retains only its visible tiles. Gray is pending, dark is absent/excluded, pink is unreadable, purple is unsupported, checkering is known air and blue outlines indicate selected cells. Point at a cell to read its exact block state.

Name and **Save to local templates** to capture a standalone `.wrbuild`. Source chunks and supporting raw NBT records are preserved, along with exact sparse masks and selected air. The library can import/export exact bytes and reopen an archive after the source has moved or gone offline. Keep Minecraft closed while capturing; source-change checks do not constitute a filesystem snapshot. Cancel stops between bounded work units. If a library copy finished before indexing was canceled, it remains available through Refresh.

Drafts and preview indexes live in application data, outside world saves. A preview first validates the entire archive and creates a disk seek index (24 bytes per selected chunk, 256 MiB cache budget), then reads only requested height slices. Capture and v2 storage have no small total selected-volume cap. Existing per-record/frame safety budgets and edit-fragmentation limits remain; see [streaming format](TEMPLATE-STREAMING.md) and [measured benchmarks](TEMPLATE-BENCHMARKS.md). Legacy v1 files retain their legacy limits and existing UI route.

Full free-camera voxel editing and automatic update installation are not part of this handoff. Update checks and verified downloads are available in Application updates; installing a downloaded package is manual. Mac and Windows share this UI and engine. Native Windows execution and Minecraft gameplay acceptance require their respective test environments.

Validation: `node qa/run.mjs --full` and `node scripts/smoke-template-editor.mjs`. The native workflow uses generated fixtures, tests actual-Y corner picking, disconnected edits, selected air, byte-exact export, restart persistence, opening without source files and unchanged source hashes. Set `WORLDRENEW_BACKGROUND_TEST=1` with a separate `WORLDRENEW_USER_DATA` for hidden isolated UI checks.
